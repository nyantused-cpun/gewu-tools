# 实测方法与结论摘要（2026-08-16）

对象：24 页售前方案 HTML（复杂成品：架构图/16 步流程图/甘特图/多域表格）。
方法：四路对照 + 全量源码真值核验（每条关键发现对照 HTML 源码定性后才采信）。

## 三路对比结论

| 路 | 模式 | 结果 |
|---|---|---|
| 插件基线 | 单图视觉问答（无上下文）× 6 页 | 3 类硬伤：业务标记（⭐=核心能力）误报为「emoji 违规」、OCR 误读 4 处（如 三层->二宝、项->页）、3/6 输出格式损坏 |
| 视觉子代理（mimo-v2.5）同 6 页 | 带简报 | 关键维度全胜：伪影识别、标记语义理解、内容级洞察（某页模块密度失衡并给出排布建议）；仅 1 处 OCR 误读 |
| 视觉子代理（mimo-v2.5）整稿 24 页 | 带简报 | 叙事线/密度分布/跨页一致性三块插件结构性缺失的能力；页码归属偏移 2 处（被截图串页带偏） |
| qwen3.7-plus 整稿 24 页（同卷 A/B） | 带简报 | 洞察上限更高（发现两套数字口径并存、跨页编号索引缺失），但 3 个核心新论断中 2.5 个经不起源码核验 |

## 固化进插件的经验

1. **简报契约第 0 条纪律声明**：子代理不执行入口协议/不向用户提问/用 read_image 读图（首跑两个子代理全卡死，修正后零复发）
2. **伪影声明 + 页码归属规则**：固定视口截图会串页，视口内下一节内容归下一页（页码偏移根因）
3. **真值核验闭环不可省**：视觉路线均有 OCR 误读与页码偏移，gewu_locate 核验后采信
4. **模型档位**：重档模型适合「出主意」（洞察上限高但误报多）、稳档模型适合「出结论」、真值核验托底

## 环境摩擦记录

- 受限沙箱禁子进程命名管道 → Chrome 直起会崩溃；宿主进程直起无此问题（gewu_prep 的实现方式）
- 视觉子代理冷启动慢（24 图耗时较长），疑似卡死时中断其当前轮次并重发任务指令
